# AGENTS.md

This repo is the tooling + guide for syncing the **Unbloarchy** fork with
upstream Omarchy. The actual merge work happens in the sibling checkout at
`../unbloarchy` — invoke the helpers from there as
`../unbloarchy-sync/sweep.py` / `transform.py`. `README.md` is the full
procedure; this file only captures what is easy to miss.

## Entry points

- `sweep.py` — rebrand sweep. Rewrites only lines a merge introduced (diffs the
  worktree against the fork's `HEAD`). Flags: `--work` (default cwd),
  `--repo` (ground-truth fork; default = `--work`, or `UNBLOARCHY_REPO`),
  `--dry` (print, don't write). Prints a `rename-needed:` section — tracked
  `omarchy`-named paths missing at the fork's `HEAD` that it cannot fix
  (it never renames files; `git mv` them).
- `transform.py` — derives the protected-token set from the fork's `HEAD`
  (disk dominance: a token stays `omarchy` iff its `omarchy` spelling is at
  least as common as its `unbloarchy` spelling). `--old <rev> --new <rev>`
  validates the transform against a past commit pair.
- Opencode commands (see `.opencode/command/`):
  - `/unbloarchy-sync` — full procedure end to end.
  - `/unbloarchy-resolve-merge-conflicts` — conflict resolution only.

## Ordering constraints

- Sweep runs **after** conflicts are resolved but **before** the merge commit:
  it diffs the worktree against the fork's `HEAD`, so a committed merge leaves
  it nothing to change.
- Regenerate shims (`bash install/helpers/generate-compat-shims.sh` in the
  fork) before running the tests below, so the compat names they check exist.

## Verification lives in the fork, not here

This repo has no tests, build, or lint. The gates (run from `../unbloarchy`):

```bash
bash test/shell.d/rebrand-integrity-test.sh   # must print "ok"
bash test/shell.d/compat-shims-test.sh        # must print "ok"
```

`rebrand-integrity-test.sh` fails on merge-new `omarchy`-named files and on
references whose `unbloarchy` twin now exists. Never continue while the
sweep's `rename-needed:` is non-empty.

## Conventions

- Sync commits are made in two steps with `git commit --no-verify`: first the
  raw resolved index, then `git add -A` for the swept worktree + regenerated
  shims (see README step 5).
- Generated `bin/omarchy-*` shims (second line: `# Generated by
  generate-compat-shims.sh; do not edit.`) are never hand-merged or edited —
  regenerate them.
